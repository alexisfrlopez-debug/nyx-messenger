## 1. Décrocher/refuser ÉCRAN VERROUILLÉ (demande n°1, trois mécanismes)

- **Intent plein écran** : la notification d'appel entrante lance
  `CallLockActivity` (NOUVEAU) directement **SUR le keyguard** (écran
  allumé — `USE_FULL_SCREEN_INTENT`, mécanisme officiel des apps
  téléphoniques). Alias de l'appelant + gros boutons ✕ Refuser / ✓
  Décrocher. Pendant l'appel : durée, muet, haut-parleur, raccrocher.
  JAMAIS de contenu de message (l'alias est déjà visible sur la
  notification elle-même). L'activité se ferme seule à la fin de l'appel ;
  le verrou biométrique de l'app reste armé dessous. Android 14+ peut
  rétrograder l'alarme plein écran en notification heads-up si l'utilisateur
  l'a refusée dans les réglages — les boutons d'action restent le repli.
- **Boutons Décrocher/Refuser SUR la notification** (`CallActionReceiver`,
  NOUVEAU) : fonctionnent SUR l'écran verrouillé, sans RIEN déverrouiller —
  le média est indépendant de l'UI, l'appel s'établit sans OUVRIR l'app.
  La notification est ongoing pendant la sonnerie.
- **Overlay d'appel AU-DESSUS du verrou de L'APP** (`NyxNavHost`) : avant,
  « verrouillé = pas d'appel vu » — l'overlay est désormais rendu par-dessus
  le verrou applicatif (alias seul visible, décision de sécurité explicite).
- **Visio verrouillée, message honnête** : aucune surface caméra sur le
  keyguard — l'émission/réception continuent, « Visio active — déverrouillez
  l'appareil pour voir l'image ».

## 2. Micro ADPCM réparé — cause racine du crash ANR (2ᵉ export)

Preuve noire sur blanc : **16 431 lignes « Error -38 » en 147 ms**
(≈112 000/s) dans le logcat — `startAdpcmEncoder` n'appelait **JAMAIS**
`rec.startRecording()` (seul le chemin AAC le faisait) → tout `read`
rendait ERROR_INVALID_OPERATION → boucle `continue` SANS temporisation →
CPU saturé + émission muette + ANR → **process tué 4 s** après
l'activation de la visio.

**Correctif** : `startRecording()` AVANT toute lecture (avec vérification
d'état honnête — micro HS = émission muette, l'appel CONTINUE en réception,
miroir v0.2.48 : jamais un appel tué pour un micro HS) + garde
anti-tourbillon : pause 20 ms sur lecture vide, coupure d'émission après
50 échecs.

## 3. Visio PC↔téléphone qui tient au décroché (miroir bureau v0.3.8)

L'appelé expédiait sa trame `F_VIDEO_ROT` **AVANT** son `F_CALL_ACCEPT`
— et tout appelant à lecture unique prenait la rotation pour « pas de
réponse » → BYE silencieux au décroché.

**Correctif** (miroir des deux côtés) : l'ACCEPT est TOUJOURS la première
trame (rotation/transmit APRÈS — interop conservée avec v0.2.53-0.3.7) ;
l'appelant lit en **boucle bornée** (`readCallAnswer`, NOUVEAU) en ROUTANT
les trames précoces au lieu d'échouer.

## 4. Latence audio tel-PC réduite (miroir bureau v0.3.8)

- tampon `AudioTrack` minimal (~128 ms) sur le chemin interop ADPCM — le
  chemin téléphone↔téléphone (AAC) est INCHANGÉ (qualité supérieure) ;
- **anti-arriéré** : écrit en avance de >150 ms sur l'horloge réelle =
  bloc SAUTÉ (rejoint le direct sans trou audible) — l'arriéré de mise
  en service (TCP + tampon) et les rafales Tor ne s'accumulent plus
  (journal « anti-arriéré : N bloc(s) sauté(s) »).
