# Nyx Desktop v0.3.1 — correctif démarrage Windows (ADR-019)

## Le problème (retour terrain, v0.3.0)

Au premier lancement sur un Windows vierge, l'application plantait immédiatement :

```
java.lang.UnsatisfiedLinkError: Unable to load library 'sodium':
Le module spécifié est introuvable.
Native library (win32-x86-64/sodium.dll) not found in resource path
```

Deux causes racines, identifiées par l'analyse du fat jar livré :

1. **Dépendance MinGW introuvable** — la dll libsodium embarquée par
   lazysodium-java est une build MinGW-w64 : elle dépend de
   `libgcc_s_seh-1.dll` (qui dépend elle-même de `libwinpthread-1.dll`),
   deux dll absentes de tout Windows sans toolchain MinGW. Le chargeur
   groupé de lazysodium (PREFER_BUNDLED) l'extrait seule vers un
   répertoire temporaire → la résolution des dépendances par Windows
   échoue → repli système silencieux → rien → crash au démarrage.
2. **Natif d'affichage Windows absent** — `compose.desktop.currentOs`
   n'embarque que le natif skiko de la plateforme de BUILD (linux) : la
   dll skiko Windows manquait également dans le jar livré.

Côté bac à sable Linux, une libsodium système masquait le problème de
chargement — d'où un smoke test trompeur en v0.3.0.

## Le correctif

- **`Natives.kt`** (nouveau) : avant toute initialisation JNA, extraction
  autonome de la libsodium de la plateforme vers `<tmp>/nyx-natives/libsodium/`
  sous le nom exact attendu par JNA, AVEC ses deux compagnes MinGW dans le
  même répertoire (résolution des dépendances depuis le répertoire de la
  dll), et déclaration du répertoire via `jna.library.path` — exploré en
  premier par JNA lors de la résolution par nom. Régression verrouillée par
  `NativesTest` : sur le bac à sable il n'existe aucune libsodium.so système
  utilisable — seule la copie extraite peut satisfaire la résolution par nom,
  la reproduction exacte de la situation Windows du terrain.
- **Fat jar** : miroir des natifs aux conventions de ressources JNA
  (`win32-x86-64/sodium.dll`, `linux-x86-64/libsodium.so`,
  `darwin-*/libsodium.dylib`) en filet de sécurité + les deux dll compagnes
  embarquées en ressources (`nyx-native/`).
- **skiko Windows** : `org.jetbrains.skiko:skiko-awt-runtime-windows-x64`
  ajouté aux dépendances — plus de téléchargement implicite au premier
  lancement (anonymat : aucune requête hors Tor) et démarrage hors ligne.
- **Installateur** : les deux dll compagnes sont posées dans `runtime\bin`
  (répertoire de java.exe — second ordre de recherche des dépendances) et
  deviennent des fichiers essentiels vérifiés à l'extraction. La version est
  affichée au démarrage de l'installateur.
- **Lanceur** : `-Xmx1g` (heap borné — machines à mémoire chargée) et
  passage des arguments au jar.
- **`--selftest`** (nouveau) : autotest headless du noyau (libsodium chargée,
  onion v3, identité scellée PBKDF2-150k + AES-256-GCM restaurée, sealed box
  + signature NYX1) — marqueurs `[SELFTEST]`, code de sortie 0/3 ; utilisé
  par le pipeline de build (`scripts/build-desktop-release.sh`) et
  diagnosticable terrain (`nyx-messenger.bat --selftest`).
- SLF4J NOP embarqué — l'avertissement de démarrage disparaît.

## Interopérabilité

Inchangée — même protocole filaire que v0.3.0 et l'Android v0.2.53
(appels audio/visio : phase 2, ADR-019 §6).

## Mise à jour

Relancer l'installateur v0.3.1 par-dessus une installation v0.3.0
(mise à jour en place — les données `%USERPROFILE%\.nyx-messenger`
sont préservées), ou décompresser le zip portable.
