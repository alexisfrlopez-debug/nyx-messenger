## Déconnexion du compte (demande opérateur)

Nouvelle carte **« Compte »** dans Paramètres (builds standard/test/test2 — le
source est commun) : affiche l'alias et l'adresse onion du compte courant, et
propose **« Déconnecter le compte »** — pour changer de compte ou en créer un
nouveau sans désinstaller l'application.

- Confirmation EXPLICITE protégée par le **mot de passe NORMAL** (c'est lui qui
  protège le compte depuis la v0.2.26) : mot de passe incorrect → refus.
- Effacement complet via le chemin audité du reset destruction
  (`security/Wipe`) : identité + clé privée, contacts, messages, médias,
  réglages (réplicas personnalisés compris), mots de passe — puis arrêt propre
  de Tor et mort du process. Au relancement : onboarding (créer un nouveau
  compte ou importer une clé de récupération).
- Rappel dans le dialogue : exporter AVANT la clé de récupération
  (Paramètres → Sauvegarde) et les conversations chiffrées (Paramètres →
  Export) — l'adresse onion disparaît avec sa clé privée.
- Cachée en session panique : l'utilisateur de la base leurre ne peut pas
  effacer le vrai compte.

## Crash « password empty » — corrigé (prouvé terrain)

Log v0.2.26-test2 (Blackview, 09:00:45) : **FATAL EXCEPTION** au thread
principal — `InvalidKeySpecException … Caused by: IllegalArgumentException:
password empty` (PBKDF2) : un champ de mot de passe confirmé **vide** arrivait
dans `PasswordVault.verify()` / `PasswordCrypto.decrypt()` (dialogs
d'importation). L'application crashait à l'appui sur le bouton.

- `PasswordVault.verify()` / `verifyAgainst()` : mot de passe vide → jamais
  haché (null/false) — garde centrale couvrant tous les points d'entrée.
- `PasswordCrypto.decrypt()` : enveloppe + mot de passe vide → null.
- Dialogs d'import (onboarding fichier + clé collée) : champ vide → erreur
  immédiate « Mot de passe incorrect », jamais de PBKDF2.
- Tests JVM ajoutés (PasswordVaultTest) : vide → null sans exception ; cycle
  encrypt/decrypt inchangé pour un mot de passe non vide.

## Appels / visio — fenêtres alignées sur le terrain

Log v0.2.26-test2 (09:04, Blackview appelant) : la sonnerie ET le décrochage
passent (le correctif anti-état collant v0.2.26 fonctionne), mais les essais
média timeout en boucle (`connexion directe impossible (Connect timed out)`)
pendant que Tor n'arrive pas à résoudre l'onion de l'appelé
(`No more HSDir available to query`, 09:03:41 — juste après un reboot de l'app
à 09:00:54 : la récupération d'annuaire HSDir peut prendre 1-3 min).

Deux désalignements corrigés :

- **Fenêtre média appelant 75 s → 150 s** : les essais de connexion directe
  survivent désormais à la récupération d'annuaire de Tor.
- **Watchdog WAIT appelé 60 s → 180 s** : l'appelé ne raccroche PLUS avant la
  fin de la fenêtre appelant — avant, il tuait l'appel que l'appelant était en
  train d'établir (c'est pourquoi « décrocher » ne donnait rien de visible).
- Le garde-fou global (4 min par phase) reste la borne de sécurité.
