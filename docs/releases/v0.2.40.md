# v0.2.40 (versionCode 44) — PRÉ-RELEASE

## Fonctionnalité principale — mise à jour automatique de la VERSION TEST

Demande opérateur (session 61) : « j'aimerais que la version test se mette
à jour automatiquement dès qu'une nouvelle version est poussée sur
github » — **le build TEST suit désormais chaque livraison GitHub sans
intervention** : détection, téléchargement via Tor et proposition
d'installation.

### Deux canaux de mise à jour disjoints

| | Build STANDARD | Build TEST (Nyx TEST) |
|---|---|---|
| Release suivie | dernière **validée** (non-pré-release) | dernière **publiée** (pré-releases **incluses**) |
| Endpoint API | `/releases/latest` | `/releases` (liste, plus récente d'abord) |
| APK retenu | `…-release.apk` | `…-test.apk` |
| Périodicité | au démarrage puis toutes les 6 h | au démarrage puis toutes les **30 min** |
| Anti-downgrade | `isNewer` (X.Y.Z, suffixes ignorés) | idem — `0.2.41` > `0.2.40-test`, jamais l'inverse |

Le canal test admet les pré-releases **par design** : c'est son rôle —
chaque livraison y est d'abord publiée en pré-release en attendant la
validation terrain (règle §9.6 du RESTART), la version test doit donc la
proposer « dès qu'elle est poussée ». Les DRAFTS restent rejetés (garde
de sécurité), les releases sans asset `-test.apk` sont sautées.

### Correctif critique inclus — l'installation était BLOQUÉE depuis v0.2.20

En écrivant le canal test, un bug latent du canal standard a été
découvert : **la permission `REQUEST_INSTALL_PACKAGES` était ABSENTE du
manifest depuis l'introduction de la mise à jour automatique (v0.2.20)**.
Or l'installateur système l'exige depuis Android 8 (minSdk 26) pour un
intent `ACTION_VIEW application/vnd.android.package-archive` : Android
rejetait silencieusement l'installation — la v0.2.20 « proposait » une
mise à jour qui ne pouvait JAMAIS s'installer. Ajoutée au manifest, avec
entrée justifiée dans la liste fermée de l'audit (`audit-allowlist.txt`).

### Ce que voit l'opérateur

1. **Bannière « Nouvelle version X prête — installer »** en tête de
   l'écran conversations (carte pleine largeur, appui = installateur
   système ; la confirmation Android reste obligatoire — règle
   plateforme) — visible sur les DEUX builds ;
2. **Notification « Mise à jour Nyx TEST prête »** (titre distinct côté
   test : l'opérateur sait QUEL Nyx installe) ;
3. **Carte Paramètres « Mise à jour de l'application »** désormais
   visible AUSSI dans le build test : description « Canal TEST : …
   pré-releases incluses », état détaillé (à jour / disponible /
   téléchargement % / prête / échec) et bouton « Vérifier maintenant ».

Le téléchargement reste **100 % via le SOCKS de Tor embarqué** (ADR-007 —
jamais de requête en clair), l'APK vit dans le cache privé
(`cache/update/`), partagé à l'installateur par le FileProvider dédié
(read-only).

- **maj-auto-carte** : carte Paramètres visible côté test, bouton
  « Vérifier maintenant », anti-downgrade ;
- **maj-auto-standard** : le build NORMAL continue d'ignorer les
  pré-releases (validation continue v0.2.20) ;
- les validations critiques v0.2.39 (HSFETCH sans 513, appels avec média,
  console v0.8.7) restent en tête de plan.

## Bugs connus

- La vérification ne tourne que lorsque l'app est OUVERTE (process en
  vie) — pas de mise à jour en arrière-plan, cohérent avec l'architecture
  v0.1 (décision 17 : pas de synchro quand le process est tué) ;
- L'installation elle-même exige toujours la confirmation utilisateur —
  Android ne permet pas une installation silencieuse sans privilèges
  système (device owner) ; « automatique » = détection + téléchargement
  automatiques, installation en 1 appui.
