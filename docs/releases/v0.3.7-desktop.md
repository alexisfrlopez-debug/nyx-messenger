(code 57)` alors que la v0.2.54 (ADPCM) est PUBLIÉE (GitHub id 426070452,

  (« aac » implicite) → le bureau envoie BYE « mise à jour requise » =
  « raccroche au décrochage » EXACT (côté téléphone : « appel actif » puis
  fin — export 00:13:56) ;
- **téléphone→PC** : le HELLO du téléphone n'annonce pas ADPCM → refus au
  moment de l'acceptation bureau (« appelant … codec « aac » seulement — le
  bureau exige l'ADPCM », export 00:13:56/00:14:28).

**Le correctif est la mise à jour du téléphone en v0.2.55** (canal test :
automatique). La note « codec « aac } » du journal est un artefact de gabarit

## 2. Accusés — couche données PROUVÉE fonctionnelle, deux défauts résiduels corrigés

## 3. Visio PC↔téléphone — codec vidéo logiciel commun MJPEG

Le bureau ne peut NI encoder NI décoder le H.264 MediaCodec d'Android en pur
Java → codec commun **MJPEG** (JPEG complet par trame, auto-contenu : une
trame perdue ne corrompt rien — même résilience Tor que les blocs ADPCM
fermes). Négociation miroir du champ audio « ac » :

- `HELLO.vc` = codecs vidéo SUPPORTÉS par l'appelant (« mjpeg » bureau ;
  « h264,mjpeg » téléphone ≥ v0.2.55 ; ABSENT = H.264 seul ≤ v0.2.54) ;
- `ACCEPT.vc` = codec CHOISI par l'appelé (« mjpeg » seulement en MJPEG —
  téléphone↔téléphone reste le format v0.2.20 **octet pour octet**) ;
- l'offre de signalisation porte l'intention visio (l'écran d'appel entrant
  affiche « visio » avant le HELLO) ;
- pair ≤ v0.2.54 → dégradation honnête en AUDIO (l'appel TIENT).

### 3.1 Bureau (v0.3.7)

- **Émission** : partage d'**écran** (`java.awt.Robot` → mise à l'échelle
  ≤480 px → JPEG q0.55, ~5 fps, boucle auto-régulée : un write bloqué par Tor
  = trame sautée, jamais de bourrage) — `DesktopCallVideo` (NOUVEAU) ;
- **Réception** : la caméra du téléphone (JPEG → skia → Compose, rotation
  F_VIDEO_ROT portée par la vue) ; `DesktopCallAudio` route F_VIDEO/
  F_VIDEO_ROT vers le moteur (l'audio reste le SEUL lecteur du socket) ;
- **UI** : la vue distante remplace l'avatar en visio, bouton « 📹 Écran
  partagé / Partage en pause », bouton 📹 du ChatPanel RÉEL (remplace le
  message « la visio reste entre téléphones »).

### 3.2 Téléphone (v0.2.55, versionCode 59)

- **Appelant** : HELLO vc="h264,mjpeg" → ACCEPT.vc="mjpeg" du bureau →
  `switchSendingToMjpeg()` (l'encodeur H.264 n'a rien émis, la caméra est
  ré-utilisée vers un ImageReader YUV) ;
- **Appelé d'un bureau** : HELLO vc="mjpeg" seul → mode MJPEG d'emblée
  (`CallVideo(useMjpeg=true)`), ACCEPT vc="mjpeg" ;
- **Émission** : ImageReader YUV_420_888 → NV21 → `YuvImage.compressToJpeg`
  (q55) → F_VIDEO ; exécuteur mono-thread + drapeau busy (gel si write
  bloqué) ; rotation toujours suivie (F_VIDEO_ROT inchangé) ;
- **Réception** : JPEG → `BitmapFactory` → Canvas (fit centré) sur la surface
  distante ;
- **Téléphone↔téléphone** : H.264 matériel inchangé, AUCUN octet nouveau sur
  le fil.
