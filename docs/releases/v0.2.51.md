# v0.2.51 — « Ça décroche… et l'appel tient »

## Contexte terrain (25/10, retour 04:58)

« maintenant ça décroche mais crash immédiat. donc on avance » — 2 exports
v0.2.50-test analysés (Xiaomi 24094RAD4G / Android 16 + Blackview XPLORE 1 /
Android 15, 04:58:53/59). Les deux fixes v0.2.50 ont TENU : sonnerie chez
l'appelé ×3 (« appel entrant de … »), décroché fonctionnel ×3 (« acceptation
utilisateur » ×3), marqueur « câblage v0.2.50 vérifié » ×2, AUCUN FATAL
(raccroché/refus hors thread UI). Mais l'appel s'effondrait ~300-700 ms
après « actif » — 3 appels × 2 téléphones, 6/6.

## Verdict — le « csd factice » qui tuait le décodeur du pair

La chaîne causale, entière dans les logs des DEUX téléphones :

1. `CallAudio.startSending()` lisait `enc.outputFormat.getByteBuffer("csd-0")`
   **immédiatement après `enc.start()`** pour annoncer le csd-0 AAC au pair
   (HELLO côté appelant, F_CALL_ACCEPT côté appelé). Or les codecs C2
   (Android 12+ ; téléphones du terrain en 15/16) n'y exposent le csd-0
   qu'**après le premier travail** du codec — preuve log Xiaomi 04:58:19.160 :
   `start: outputFormat: AMessage` **sans aucun champ**, premier
   `queueInputBuffer` à 19.353, bien après la lecture ;
2. la lecture rendait donc `null` → le repli `?: ByteArray(2)` expédiait un
   « csd factice » `{0x00,0x00}` (profile 0 = réservé, indécodable) ;
3. le DÉCODEUR DU PAIR, configuré avec ce csd, mourait au démarrage :
   « The csd Sample queue » → « work failed to complete: 14 » →
   `err 0xe/14` état STARTED → UNINITIALIZED — signature identique chez
   les 2 téléphones, 3 appels chacun (6/6, déterministe) ;
4. sa première trame F_AUDIO arrivait → `dequeueInputBuffer` sur codec
   mort → `IllegalStateException` → boucle de lecture `catch` → `onFatal`
   → `end()` → l'appel s'effondre : AudioRecord stoppé, AudioTrack détruit
   **« 0 frames delivered »**, encodeur stoppé — et l'appel suivant était
   retenté 8 s plus tard (terrain : 3 appels en 30 s) ;
5. l'app ELLE-MÊME survivait (aucun FATAL — le correctif v0.2.50 du
   raccroché tient) : « crash immédiat » = l'écran d'appel qui retombe
   aussitôt.

C'est un bug LATENT de la v0.2.18 (le CSD se lit toujours à cet endroit) :
il n'était jamais apparu parce qu'aucune version n'avait JAMAIS atteint le
pipeline média en terrain (v0.2.44-49 : onion jamais servi / offre invisible /
micro jamais demandé). La sonnerie et le décroché réparés, la couche
suivante est exposée — « on avance ».

## Correctif

- **`AacCsd` (nouveau, objet PUR, 10 tests JVM)** : l'AudioSpecificConfig
  est une fonction PURE du format configuré (profile AAC-LC, fréquence,
  canaux) — on la **CALCULE** au lieu de la lire dans une fenêtre de course.
  Vecteur de référence : AAC-LC 44100 stéréo = `12 10` ; notre appel
  (16 kHz mono) = `14 08`. `looksBroken` détecte le csd factice (vide ou
  tout-nul) ; `sanitize` le remplace par le csd local calculé ;
- **`startSending`** : csd calculé quand le codec ne l'expose pas (marqueur
  « csd-0 AAC CALCULÉ (1408) — le codec ne l'expose pas encore au
  démarrage (C2 : null)… ») ; les DEUX replis micro (permission refusée /
  AudioRecord mort) renvoient le csd **calculé** — jamais `{0,0}` : sans
  émission, le pair décode du VRAI silence (avant : son décodeur mourrait
  sur notre csd factice, tuant l'appel pour lui aussi) ;
- **`startReceiving`** : csd du pair **assaini** — un pair resté en v0.2.50
  envoie toujours le csd factice : il est remplacé par le calcul local
  (marqueur « csd-0 pair INVALIDE (2 o) — remplacé par le calcul local
  (1408) : pair v0.2.50 ? décodeur sauvé, appel maintenu »). La config audio
  étant FIXE des deux côtés (AAC-LC 16 kHz mono — aucune négociation dans le
  protocole), le csd calculé est TOUJOURS le bon : **un appel v0.2.51 ↔
  v0.2.50 tient**. Le csd-0 est désormais TOUJOURS configuré côté décodeur
  (l'AAC brut sans csd est indécodable) ;
- **Marqueur de câblage v0.2.51** : « câblage v0.2.51 vérifié : csd-0 AAC
  calculé (plus de csd factice qui tue le décodeur du pair), offre sur la
  boîte du pair puis flotte, poll réplica propre + flotte, raccroché et
  refus hors thread UI, tirage NYX-LINK flotte seule, verrou média
  ACCEPTED||PENDING ».
