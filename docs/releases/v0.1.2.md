# Nyx v0.1.2 — biométrie locale opt-in + alias unique (invitations)

Deux nouvelles fonctionnalités demandées par l'opérateur (session 10), cadrées
par **ADR-010** (biométrie) et **wire-format.md §6 / api.md** (alias).

## 1. Verrou biométrique local (opt-in)

- **À l'installation** (onboarding) : option « Protéger l'accès par biométrie » —
  l'activation demande une confirmation OS immédiate (le device doit avoir une
  empreinte/visage ou un code enregistré).
- **Comportement** : écran de verrou AVANT tout contenu — à froid, après chaque
  retour au premier plan ; prompt automatique avec repli sur le code de
  l'appareil (`BIOMETRIC_WEAK | DEVICE_CREDENTIAL`).
- **Confidentialité (ADR-010 §3)** : la vérification est effectuée par l'OS —
  l'application ne reçoit qu'un succès/échec ; **aucune donnée biométrique
  n'est lue, stockée ou transmise**. Permissions ajoutées au manifest fusionné :
  `USE_BIOMETRIC`/`USE_FINGERPRINT` uniquement (déverrouillage local).
- **Cas dégradé** : si le device n'a plus aucun moyen de vérification, l'écran
  de verrou propose explicitement de désactiver l'opt-in.

## 2. Alias unique (pseudonyme pour les invitations)

- **À l'onboarding** : champ optionnel « Votre alias » (format `^[a-z0-9_]{3,24}$`,
  normalisation automatique), vérification de disponibilité sur le réplica
  rattaché, **suggestions automatiques si l'alias est déjà pris** (variations
  numérotées re-vérifiables).
- **Réservation protocolaire** : l'alias est un événement journal signé
  (`type="alias"`, claim) comme toute donnée Nyx — pas d'annuaire central ;
  convergence déterministe entre réplicas (le plus petit `id` gagne).
  Sans réplica joignable, la réservation est **différée** et part
  automatiquement à la première connexion.
- **Invitations** : partagez `@votre_alias` ou votre adresse onion. Le serveur
  expose `GET /client/alias?name=` (résolution point à point ; pas de listing
  global — anti-énumération). L'alias est optionnel et public : ne jamais y
  mettre de nom réel (ADR-010).
- **Serveur** : support complet (validation, index déterministe, endpoint) —
  2 nouveaux tests Go verts (circuit claim→résolution, convergence min-id +
  replay) ; 4 nouveaux tests Kotlin (validateur, aligné sur le serveur).

## Confidentialité — rappel (ADR-010)

Nyx ne collecte **aucune** donnée d'identité réelle : pas de photo, pas de KYC,
aucune collecte cachée. La modération se fait par mécanismes protocolaires
(signalements signés, blocklists — feuille de route ADR-010 §2).
