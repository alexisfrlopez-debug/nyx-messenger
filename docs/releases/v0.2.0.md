# Nyx v0.2.0 — API admin serveur + profil à visibilité par champ + contacts par alias

> Publiée le 2026-10-12 (session 12). Installation : télécharger l'APK signé,
> l'installer par-dessus v0.1.2 (même signature — mise à jour directe).

## 🆕 Application (v0.1.2 → v0.2.0)

### Profil à visibilité par champ (wire-format.md §7)
- Nouvel écran **« Mon profil »** (menu ⋮ de la liste des conversations) :
  nom affiché, bio, site web, localisation, **photo de profil** (sélecteur
  système, recodage local 256×256 — aucune permission requise).
- **Interrupteur public/privé par champ** : « privé » = le champ ne quitte
  JAMAIS l'appareil ; « public » = diffusé dans le journal (type `profile`,
  visible par qui consulte votre identité). **Rien n'est public par défaut**
  (ADR-010 : publication = choix explicite).
- Consultation de la **carte publique d'un contact** depuis le chat (icône
  profil) — requête uniquement à la demande explicite de l'utilisateur.

### Ajouter un contact par alias unique
- Le champ d'ajout accepte désormais **l'alias** (`@pseudo`, wire-format.md §6)
  OU l'adresse onion : détection automatique.
- L'alias est résolu via `GET /client/alias` (règle déterministe du plus petit
  id — session 10) et le contact est enregistré avec son adresse onion réelle.

### « Mon adresse Nyx » (menu ⋮)
- Affichage de **votre adresse onion** (votre identité) + alias d'invitation.
- **Copier** et **Partager** (feuille de partage système : vous choisissez le
  canal — Nyx ne transmet rien de son côté).

### Paramètres (menu ⋮)
- **Thème** : système / clair / sombre.
- **Fermeture de l'application** : demander à chaque fois / réduire /
  quitter complètement.
- **Verrou biométrique** (opt-in local, ADR-010 §3 — désormais réglable ici
  aussi).

### Dialogue de fermeture
- À la fermeture, l'app demande : **« Réduire (Tor actif) »** — Tor et les
  notifications restent actifs, la réception continue en arrière-plan — ou
  **« Quitter complètement »** — tous les processus, Tor compris, sont tués
  proprement (arrêt du service au premier plan → destruction du démon tor
  enfant, puis fin de la tâche).

## 🖥️ Serveur (0.1.0 → 0.2.0)

### API admin complète (`/admin/*`)
Implémentation de la spécification de la console nyx-admin (dépôt privé
APPLI_ADMIN.md — ADR-008) :
- **2 barrières** : onion d'admin DÉDIÉ (port 9091, publié séparément dès
  qu'une clé admin est configurée) + signature ed25519 de chaque commande
  (chaîne canonique `nyx-admin-v1`, fenêtre ±120 s, cache de nonce anti-replay).
- **Monitoring** : `GET /admin/status`, `/admin/resources` (CPU/RAM/disque
  via /proc), `/admin/peers` (curseurs, latence, backoff), `/admin/log`.
- **Actions** : maintenance (503 clients, gossip maintenu), shutdown/restart
  gracieux, ajout/retrait de pairs, resync de curseur.
- **Élagage vérifiable** : `checkpoint/propose` (racine de Merkle RFC 6962 du
  préfixe, signée par la clé onion) puis `checkpoint/apply` (archivage hors
  ligne + troncature) — la suppression unitaire reste interdite (ADR-001).
- **Clés** : ajout/révocation d'appareils admin (garde anti-verrouillage sur
  la dernière clé) ; rotation d'identité = 501 honnête (roadmap v0.4).
- Journal d'audit local de toutes les commandes (qui/quoi/quand/code).
- Sans `admin.authorized_keys` dans la config : **aucune surface admin n'est
  publiée** (défaut sûr).

### Protocole
- Nouveau type d'événement **`profile`** (wire-format.md §7) : carte publique
  à visibilité par champ, clés fermées, limites de taille, **invariant
  serveur** — un champ `public:false` dans une diffusion est rejeté (400) ;
  derniers seq gagne (§7.3). `GET /client/profile?author=` (api.md v1.2).
- Les routes client répondent 503 pendant la maintenance (gossip maintenu).
