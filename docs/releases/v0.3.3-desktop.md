# v0.3.3-desktop — VERSION TEST : correctif connexion Tor/réplicas + bouton d'envoi de logs

**Date** : 2026-10-27 (session 73) · **Retour terrain opérateur** (verbatim) :
« l'appli windows ne se connecte pas à tor ni aux replicas + je veux une
version test avec le bouton d'envoi de logs comme pour la version android »

## 1. Diagnostic (analyse code — les journaux terrain arriveront par le nouveau bouton)

Quatre aveuglements expliquaient un desktop qui « ne se connecte pas » sans
qu'aucune cause ne soit objectivable :

1. **Le démarrage de Tor BLOQUAIT le thread UI AWT** : `startBackend()` était
   appelé depuis `LaunchedEffect` (thread de composition) et attendant
   séquentiellement le cookie (≤ 60 s) PUIS le bootstrap (≤ 180 s) — jusqu'à
   **4 minutes de fenêtre gelée** (« Ne répond pas »), progression jamais
   peinte. Un échec n'était visible qu'après le gel : l'utilisateur voyait une
   application morte.
2. **La console du démon tor était avalée** : le drain jetait stdout/stderr —
   un `tor.exe` mort immédiatement (dll, antivirus, DataDirectory verrouillé)
   produisait l'erreur générique « le démon tor est mort (voir tor/tor.log) »
   alors que tor.log peut ne pas exister (mort avant l'ouverture du Log).
3. **Aucun retry, aucun nettoyage** : l'Android a `TorManager` idempotent +
   `retry()` + `killLeftoverTor` (ADR-007 rév. v0.2.9) — le desktop n'avait
   RIEN porté : un tor.exe orphelin (crash v0.3.0, Task Manager sur javaw)
   verrouille le DataDirectory → tout nouveau démon meurt « Tor is already
   running » → connexion impossible jusqu'au reboot de Windows.
4. **Journaux en mémoire uniquement** : tout le contexte d'un démarrage raté
   se perdait au redémarrage de l'app (l'Android a réglé ça en v0.2.33 avec
   l'anneau DiagLog persistant).

## 2. Correctifs livrés

| # | Correctif | Détail |
|---|-----------|--------|
| 1 | **UI non bloquante** | `startBackend` part sur `Dispatchers.IO`, retour immédiat ; bannière Tor peinte en direct (pourcentage de bootstrap) |
| 2 | **Retry automatique 1× + bouton « Réessayer »** | 2ᵉ tentative automatique après kill des tor orphelins ; bouton dans la bannière Tor quand FAILED — plus d'impasse jusqu'au redémarrage |
| 3 | **killLeftoverTor porté** | ciblage STRICT par chemin d'exécutable (jamais le tor du navigateur Tor Browser) ; PowerShell `Win32_Process` borné 8 s (Windows) / `pgrep` (bac à sable) |
| 4 | **Erreurs explicites** | la queue de la console du démon + la fin de tor.log alimentent l'exception → affichées dans la bannière ET le journal |
| 5 | **Journal persistant** | `<dataDir>/logs/nyx-desktop.log`, borné ≈ 512 Ko (rotation à 1 Mo) — survit aux crash/redémarrages |
| 6 | **Progression bootstrap journalisée** | marqueurs `nyx-tor` « bootstrap N% » (comme l'Android) |
| 7 | **GeoIP embarqué** | geoip/geoip6 de l'expert bundle livrés + torrc `GeoIPFile`/`GeoIPv6File` best-effort, fichiers essentiels de l'installateur |
| 8 | **Message antivirus** | binaire tor introuvable → « tor.exe a été supprimé ou bloqué ? (antivirus : ajoutez le dossier Nyx aux exclusions et réinstallez) » |

## 3. Bouton « ENVOYER LES LOGS » (version test — miroir Android)

Demande opérateur : « comme pour la version android ». Portage complet du
trio Android :

- **`diag/DriveUploader.kt`** — flow refresh-token OAuth + upload multipart
  Drive API v3 en HttpURLConnection stdlib (zéro dépendance). Credentials
  embarqués DANS LE JAR au build depuis `desktop/test-upload.properties`
  (git-ignoré, miroir `android/test-upload.properties`, dossier « Tokens »
  §6) + **override terrain** `<dataDir>/drive-upload.properties` sans rebuild
  (leçon Android v0.2.9 : refresh token révoqué/expiré). Déviation ADR-007
  assumée et inchangée : cet appel ne passe PAS par Tor (sorties Tor
  massivement bloquées par Google).
- **`diag/LogCollector.kt`** — en-tête (version, OS, Java, état Tor + onion,
  binaire tor résolu, réplicas actifs/découverts/rendezvous/personnalisé,
  réplique embarquée) + tor.log (fin) + console du démon + journal persistant
  + journal mémoire. Aucune donnée de conversation, aucune clé.
- **`ui/TestLogExportCard.kt`** — carte repliable rouge en tête des
  conversations (leçons Android v0.2.38 repli + v0.2.42 statut court/contraint)
  : gros bouton rouge « ENVOYER LES LOGS » (dépôt Drive logs-terrain — même
  dossier que les exports Android) + recours « Enregistrer dans un fichier… »
  (JFileChooser = équivalent desktop du partage système ACTION_SEND).

## 4. Répliques — guidance terrain
