# Nyx v0.2.19 — Onglet fichiers & médias, suppression unitaire (locale + à distance), réplica temporaire « test 2 »

versionCode 23 — trois APK : `standard`, `test`, **`test2`** (NOUVEAU).

## 1. Onglet « Fichiers & médias » dans chaque chat (demande opérateur)

- La fenêtre de chat gagne un **TabRow à deux onglets** : « Messages » et « Fichiers & médias ».
- L'onglet médias liste **tous les transferts de la conversation** (photos, vidéos, notes vocales, documents), du plus récent au plus ancien, avec : vignette (images, décodée depuis le stockage chiffré) ou icône par type, nom, taille, direction (Envoyé/Reçu) et date.
- **Appui** sur une ligne : ouvre la visionneuse plein écran pour une image ; enregistre dans Téléchargements pour tout le reste (même comportement que la bulle).
- Transferts en cours : ligne visible avec état « … » ; échecs marqués.

## 2. Suppression des messages et médias (demande opérateur)

- **Appui long** sur une bulle (texte ou média) dans le chat, ou sur une ligne de l'onglet médias → dialogue de suppression.
- **« Supprimer pour moi »** — toujours disponible : efface la copie locale (ligne de message + fichier chiffré sur disque + fragments + méta). C'est la seule option offerte au **destinataire** d'un message.
- **« Supprimer pour tous »** — proposée uniquement pour les messages dont **nous sommes l'expéditeur** : efface la copie locale ET dépose chez le pair une demande signée (type « contact », corps chiffré `{"alias":…,"del":[…]}` — type DÉJÀ whitelisté par le réplica : **zéro changement serveur**). Le destinataire effacera sa copie à son prochain poll.
- **Asymétrie garantie par construction** (exigence : « suppression côté destinataire quand on est expéditeur, mais pas de suppression côté expéditeur quand on est destinataire ») :
  - l'UI n'offre « pour tous » qu'aux messages sortants ;
  - la garde SQL côté réception (`DELETE … WHERE peerOnion = auteur AND outgoing = 0`) ne peut **jamais** toucher les messages du demandeur — un pair malveillant ne peut effacer que ce que lui-même nous a envoyé.
- **Fiabilité** : la demande de suppression émise alors que le réplica est injoignable est mémorisée (nouvelle table `del_pending`) et repart par la boucle périodique — même mécanique que les accusés et les acks.
- Les listes (aperçu du dernier message, non-lus) et l'onglet médias se mettent à jour automatiquement (Flux Room).

## 3. Réplica temporaire embarqué — version « TEST 2 » uniquement (demande opérateur)

> « lorsque l'application est lancée, le téléphone devienne lui-même un replica temporaire mais il ne faut pas que ça bouffe trop de ressource/bande passante/forfait de données (mais ce sera sur une version "test 2" de l'application jusqu'à validation pour intégrer ça dans les versions "normale" et "test") »

- **Nouveau flavor `diag2` = l'APK « Nyx TEST 2 »** (`net.nyx.messenger.test2`, cohabite avec standard et test). Le réplica embarqué n'y est compilé QUE dans cette version (`BuildConfig.EMBEDDED_REPLICA`) — validation terrain avant intégration aux versions normale et test, conformément à la demande.
- **Principe** : tant que l'application tourne (mode normal), le téléphone sert **les mêmes 5 routes que le serveur Go** (`/health`, `/client/event`, `/client/inbox`, `/client/alias`, `/client/profile` — tout ce que le client sait parler) sur le **port 80 de son onion d'identité** (3ᵉ mappage ADD_ONION). Un contact ajoute donc simplement `…onion:80` dans ses réplicas : le réseau fonctionne **sans le serveur central**.
- **Portage du journal Go en Kotlin** (miroir exact) : validation complète des dépôts (types connus, corps ≤ 256 Ko base64, dérive horloge ≤ 24 h, **signature ed25519 vérifiée**), séquence stricte par auteur avec mise en attente des événements futurs et **messages d'erreur identiques** (« seq N en attente (attendu M) ») pour que l'auto-réparation du client fonctionne à l'identique, déduplication par ID canonique, résolution d'alias (règle du plus petit id) et carte de profil publique (dernier seq gagne).
- **Sobriété (exigence explicite)** :
  - dépôts limités à **60/minute par auteur** (limiteur glissant) ;
  - plafonds de stockage : **3 000 événements / 48 MiB au total / 500 par boîte** (évacuation des plus anciens) ;
  - **purge automatique après 48 h** (boucle toutes les 10 min) + bouton « Vider maintenant » ;
  - corps bornés 256 Ko ; écouteur **loopback** (tout transite par Tor) ; à l'arrêt de l'application, le réplica disparaît avec elle ;
  - dépôts **réservés à nos contacts** (statut accepté ou en attente), destinataires limités à nos contacts ou à nous-mêmes ; la lecture d'une boîte exige la **signature du détenteur de l'adresse** (paramètre `auth` — ignoré par le serveur Go, donc compatible avec les deux).
- **Stockage** : événements OPAQUES (corps chiffrés E2E, jamais déchiffrés par le réplica) dans la base SQLCipher (nouvelles tables `replica_events`/`replica_state` — migration Room v6→v7 **additive**).
- **Paramètres (test 2)** : carte « Réplica temporaire » — interrupteur (actif par défaut), adresse `…onion:80` à copier, statistiques (événements/stockage), purge manuelle ; carte « Réplicas » — ajout/retrait d'adresses custom **placées avant** les réplicas d'amorçage (le premier de la liste est utilisé pour l'envoi et la boîte).
- **Limites documentées de la phase de validation** : pas encore de gossip inter-réplicas — les deux téléphones doivent pointer vers le MÊME réplica (le premier de la liste). Sans gossip, un événement déposé sur le réplica temporaire n'est pas répliqué vers le serveur central ; si le téléphone-hôte est hors ligne, ses pairs basculent leur liste sur le serveur central, mais les événements en attente sur le réplica éteint attendront son retour (ou seront éventuellement purgés après 48 h).

## 4. Technique

- Migration Room **v6 → v7 additive** : `del_pending` (suppressions différées), `replica_events` + `replica_state` (réplica embarqué — vides hors test 2). Aucune donnée détruite, aucun changement serveur, aucune permission nouvelle.
- **93 tests JVM verts** (+26 : `DeleteCodecTest`, `ReplicaHttpTest`/`ReplicaValidateTest`/`ReplicaQuotaTest`) — parsing HTTP minimal, validation miroir du serveur Go, limiteur de débit, codec de suppression (mutual exclusion avec les accusés).
- `build-apk.sh` : **3 variants** (`assembleStandardRelease`, `assembleDiagRelease`, `assembleDiag2Release`), vérification d'autonomie × 3, livrables et SHA256SUMS à 3 entrées ; `release.sh` accepte `--test2-apk`.

## À tester (terrain, dans l'ordre)

### Sur les DEUX téléphones — installer « Nyx TEST 2 » 0.2.19-test2 (par-dessus 0.2.18-test, même signature pour le même suffixe `.test2`… la première installation de test2 peut cohabiter avec TEST si vous le souhaitez)

1. **Onglet médias** : ouvrir une conversation avec historique (photos/vocaux) → onglet « Fichiers & médias » → vérifier la liste (vignettes, tailles, direction, dates) ; appui image = visionneuse ; appui fichier = enregistrement Téléchargements.
2. **Suppression locale** : appui long sur un message texte → « Supprimer pour moi » → la bulle disparaît ; refaire sur un média dans l'onglet médias.
3. **Suppression à distance** (asymétrie) : sur XIAOMI, appui long sur un de VOS messages → « Supprimer pour tous » → attendre le poll (~15 s) sur BLACKVIEW : le message doit disparaître chez lui aussi. Inversement, sur BLACKVIEW, appui long sur un message reçu de XIAOMI : seule « Supprimer pour moi » doit être proposée — et la copie de XIAOMI doit rester intacte.
4. **Suppression hors ligne** : couper Tor (ou avion+Tor indisponible), supprimer « pour tous » → demande mémorisée ; rétablir → la demande part (voir log `nyx-send`).
5. **Réplica temporaire** : Paramètres → « Réplica temporaire » → vérifier statut Actif + adresse `…onion:80` + compteurs à 0. Copier l'adresse.
6. **Rattachement** : sur l'AUTRE téléphone, Paramètres → « Réplicas » → ajouter l'adresse copiée (elle passe en tête de liste). La ligne d'état réplica (liste des conversations) doit devenir « connecté ».
7. **Cycle complet sans serveur central** : envoyer un message + une photo → l'autre téléphone les reçoit (les dépôts et l'inbox passent alors par le téléphone-réplica ; vérifier dans Paramètres → compteurs d'événements > 0).
8. **Ressources** : laisser tourner 10 min — pas d'échauffement anormal ; Paramètres → purge manuelle → compteurs à 0.
9. **Régressions** : appels audio, notes vocales, accusés ✓✓, notifications d'invitation, verrou/biométrie, 3 mots de passe.
