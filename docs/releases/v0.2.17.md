# v0.2.17 — Pièces jointes (photos / vidéos / fichiers / notes vocales) + auto-guérison Tor

versionCode 21 · built 2026-10-17 · zéro changement serveur, zéro déploiement réplica

## Ce que cette version apporte (demande opérateur : « j'aimerais implémenter toutes les
## "feature" qu'on a sur les autres messengers (partage photo/video, partage de fichier,
## appels visio etc...) »)

### 1. Pièces jointes — photos, vidéos, fichiers, notes vocales

- **Bouton 📎** dans le chat : « Photo ou vidéo » (picker système) ou « Fichier »
  (sélecteur de documents, tout type).
- **Notes vocales** : bouton 🎤 (appuyer = enregistrer, appuyer encore = envoyer).
  Lecture intégrée dans la bulle du destinataire (▶/⏸). Permission micro demandée
  à la première utilisation.
- **Transport** : chaque fichier est chiffré E2E puis découpé en fragments de
  96 Ko ; chaque fragment part comme un événement « msg » signé (type DÉJÀ
  whitelisté par le réplica v0.2.0, corps chiffré opaque) — **zéro changement
  serveur, zéro déploiement**. Le destinataire réassemble, **vérifie le sha256**
  du fichier complet (aucun média corrompu n'est affiché) et efface les fragments
  de la base.
- **Images** : recompression locale ≤ 1600 px JPEG (une photo d'appareil de 2-8 Mo
  tombe à 150-400 Ko — 2-5 fragments au lieu de 20-90, le transport onion
  tournant à ~100 Ko/s). Aperçu dans la bulle + visionneuse plein écran
  (enregistrement dans Téléchargements en un appui).
- **Vidéos / fichiers** : carte nom + taille ; appui = enregistrement dans
  Téléchargements (MediaStore, Android 15/16 OK).
- **Progression** : barre de progression dans la bulle, côté expéditeur (dépôt
  des fragments) ET côté destinataire (fragments reçus / total).
- **Accusés v0.2.15 conservés** : ✓ Envoyé / ✓✓ Reçu / ✓✓ Lu s'appliquent aussi
  aux pièces jointes.
- **Limite** : 64 Mo par fichier (garde-fou UX — un transfert traverse Tor en
  fragments séquentiels, comptez ~1-3 min par 10 Mo selon la qualité du circuit).
- **Base** : Room v5 → v6, MIGRATION ADDITIVE (messages +2 colonnes kind/fid,
  tables neuves `attachments` + `attachment_chunks`) — aucune donnée détruite.
- **Compatibilité** : un client v0.2.16 qui reçoit un fragment le stocke comme un
  message texte (JSON brut, cosmétique, sans effet de bord) — installer la
  v0.2.17 sur les DEUX téléphones pour le partage réel.

### 2. Auto-guérison Tor — fin de la relance manuelle de l'app

Retour terrain v0.2.16 : « il faut parfois relancer l'app pour la connexion au
réplica ». Diagnostic (export Xiaomi 04:28) : 4× `GET /health ÉCHEC (20-40 s) :
SocketException: Malformed reply from SOCKS server` **alors que Tor affichait
Ready** — le démon tor se bloque en session (SOCKS cassé, circuits morts) et la
relance de l'app était le seul remède. La v0.2.17 applique ce remède
AUTOMATIQUEMENT :

- 3 échecs de TRANSPORT consécutifs du poll inbox (hors erreurs métier HTTP —
  un « HTTP 409 » prouve que tor ET le réplica répondent) → **redémarrage propre
  du démon tor** (`TorManager.retry()` — le stopNow borné de v0.2.9, exactement
  ce que fait la relance de l'app), avec cooldown de 5 min (aucune boucle).
- Trace dédiée `nyx-tor-heal` dans les exports.

### 3. Sondes réplica single-flight

Le même export montrait 4 sondes `/health` simultanées saturant le SOCKS tor
pendant son bootstrap. Désormais une seule sonde à la fois (les appels
concurrents repartent avec le dernier rapport).

### 4. Poll inbox borné (limit=32)

Le serveur répond par défaut avec jusqu'à 500 événements par GET — avec des
fragments de 171 Ko en vol, une réponse pouvait dépasser la minute Tor. Le
client demande désormais des lots de 32 (≈ 5,5 Mo max par poll, largement dans
le readTimeout de 120 s ; le curseur serveur recadre — rien n'est perdu).

## À tester sur le terrain (les 2 téléphones en v0.2.17)

1. **Pièces jointes** : envoyer une photo (depuis la galerie) → vérifier
   l'aperçu dans la bulle côté émetteur, la réception + aperçu côté destinataire,
   ouvrir la visionneuse, enregistrer dans Téléchargements.
2. **Vidéo courte** (quelques secondes) : réception carte nom+taille →
   enregistrement Téléchargements → lecture depuis Téléchargements.
3. **Fichier** (PDF ou autre) : même cycle.
4. **Note vocale** : 🎤 → parler → appui = envoi → réception → ▶ lecture.
5. **Progression** : envoyer une photo lourde et observer la barre dans la
   bulle des deux côtés.
6. **Accusés sur média** : ✓ Envoyé → ✓✓ Reçu → ✓✓ Lu sous une pièce jointe.
7. **Auto-guérison** : laisser l'app ouverte longtemps (ou en zone réseau
   instable) ; si le réplica se coupe, observer le retour SANS relance
   (ligne « Réplica connecté » sur la liste, trace `nyx-tor-heal` dans
   l'export si ça se reproduit).
8. **Régressions** : cycle texte + accusés + invitations v0.2.14/15/16 inchangés.
