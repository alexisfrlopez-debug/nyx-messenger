# Nyx v0.2.7

## Fix n°1 — régression « réplica injoignable » : filtre des réplicas d'amorçage

Cause racine prouvée par l'export v0.2.6-test (bouton rouge, Blackview XPLORE 1,
2026-10-15 16:36) : au boot, l'app logue

```
nyx-boot: aucun réplica d'amorçage embarqué — réseau en attente de configuration
```

alors que l'entête d'export affiche le réplica embarqué. Explication : le
filtre du démarrage (`endsWith(".onion")`) rejette l'adresse **avec son port**
(`…onion:80` — format écrit dans `replica-bootstrap.properties` depuis la
v0.2.6), donc la liste ACTIVE restait vide et la sonde réplica n'était jamais
lancée. La v0.2.5 embarquait l'adresse SANS port, d'où le « ça marchait avant » :
Tor, le réseau et le serveur n'étaient pas en cause. L'entête d'export aggravait
le diagnostic en affichant la chaîne brute embarquée (toujours renseignée).

## Correctif n°1

- **`BootstrapReplicas.parse`** (nouveau, pur JVM, 10 tests) : accepte
  `<56 base32>.onion` **et** `<56 base32>.onion:<port>`, séparateurs
  `, ; espace tab retour-ligne`, casse libre, doublons éliminés, garbage écarté.
  Le port est conservé (un réplica peut écouter ailleurs que sur 80).
- **Entête d'export de logs honnête** : le build test affiche désormais
  `réplicas actifs` (la liste réellement utilisée par la sonde) ET
  `réplicas embarqués` (la chaîne brute) — fini le faux diagnostic.

## Fix n°2 — crashes FATAL du service Tor (Android 15/16)

L'export v0.2.6 contient 4 crash `AndroidRuntime` sur NyxTorService :

```
ForegroundServiceDidNotStopInTimeException: A foreground service of type
dataSync did not stop within its timeout
ForegroundServiceStartNotAllowedException: Time limit already exhausted for
foreground service type dataSync
```

Android 14+ plafonne le type FGS `dataSync` à ~6 h/24 h : le démon tor tournait
des heures (heartbeat « uptime 8:07 »), le système tuait l'app, puis refusait
les redémarrages → crash en boucle (12:51, 13:24, 14:28) et Tor mort jusqu'au
lancement manuel suivant.

## Correctif n°2

- **Type FGS `specialUse`** (manifeste) : remplace `dataSync` — aucun plafond
  de durée, type plateforme prévu pour les cas sans catégorie prédéfinie
  (proxy Tor local, ADR-007) ; sous-type déclaré via
  `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`. Permission
  `FOREGROUND_SERVICE_SPECIAL_USE` à la place de `…_DATA_SYNC`.
- **Dégradation propre** : `startForeground` est enveloppé — si Android refuse
  la promotion (quota épuisé, OEM restrictif), le service logue et continue
  sans notification persistante au lieu de crasher.

## Hygiène

- `testOptions.unitTests.isReturnDefaultValues = true` : la suite JVM passe
  enfin complète (32 tests × 2 flavors — AppLockTest échouait à tort sur
  « Log not mocked » depuis la v0.2.3).

## Vérifications livrées

- Tests unitaires : 32/32 × 2 flavors (dont 10 tests du parseur, cas n°2 =

- Audit pré-compilation strict : PASSED.
- Autonomie 13+13 contrôles : signature 1 clic, Tor embarqué 4 ABI, APK

## Installation

Deux APK (règle release v0.2.2) :

- `nyx-v0.2.7-…-release.apk` — build standard (`net.nyx.messenger`).
- `nyx-v0.2.7-…-test.apk` — build test (`net.nyx.messenger.test`, cohabite
  avec le standard) : gros bouton rouge d'export des logs vers le dossier de
  travail Drive, présent sur l'écran Connexions, l'onboarding et les
  conversations.

Mettre à jour depuis la v0.2.6-test : installer par-dessus (même signature) —
identité et réglages conservés.

## Attendu au premier lancement

Écran Connexions : étape 1 « Tor » verte en ~5 s, étape 2 « Réplica » verte en
quelques secondes (sonde GET /health via Tor toutes les 8 s), puis avance
automatique vers l'onboarding (création d'identité désormais possible) ou les
conversations. En cas de blocage, l'export (bouton rouge) montrera désormais
la ligne `réplicas actifs` — vide = problème de parse/config, renseignée +
erreur = problème réseau/serveur.
