# Nyx Desktop v0.3.2 — correctifs retour terrain v0.3.1

**Date** : 27/10/2026 — **Famille** : CLIENT DESKTOP WINDOWS v0.3.2 (ADR-019,
portage du client Android v0.2.53 — le protocole, les livrables Android et le
serveur Go ne changent PAS).

## Contexte terrain

Deux retours de l'opérateur après installation de v0.3.1 sur Windows 11
(compte réel, données préservées) :

1. **« Après l'installation, je ne trouve pas le raccourci sur le bureau »**
   — l'installateur créait bien le .lnk, mais dans un dossier qui n'est pas
   le bureau réel : `%OneDrive%` (racine du dossier synchronisé, PAS le
   Bureau — redirection « Known Folder Move ») dès que la synchro OneDrive
   est active, ou `%USERPROFILE%\Desktop` qui **n'existe pas** sur un
   Windows français (le dossier physique s'appelle « Bureau »). Dans les
   deux cas : raccourci invisible. L'icône pointait en sus sur le .bat
   (aucune ressource d'icône → tuile générique cmd).

2. **« Je n'arrive pas à restaurer un fichier de sauvegarde de compte que
   j'ai généré avec l'appli téléphone »** — depuis la v0.2.26 Android, la
   sauvegarde de compte est un fichier **chiffré** (enveloppe
   `nyx-enc-v1.<sel>.<iv>.<chiffré>`, PBKDF2-HMAC-SHA256 150 000 it. +
   AES-256-GCM) contenant le JSON v2 (clé + alias + profil + contacts +
   curseurs). L'onboarding bureau n'acceptait QUE la clé nue collée
   `nyx1.…` (bouton sinon désactivé) : aucun sélecteur de fichier, aucun
   déchiffrement, aucune lecture du JSON v2 — l'import était
   structurellement impossible.

## Correctifs

### 1. Raccourcis créés au bon endroit, avec l'icône Nyx

- `desktop/installer/main.go` : le dossier cible est résolu PAR L'API SHELL
  dans la commande PowerShell elle-même —
  `[Environment]::GetFolderPath('Desktop')` / `('Programs')`
  (SHGetKnownFolderPath) — ce qui couvre d'un coup la redirection OneDrive,
  les dossiers localisés (Bureau fr-FR, Escritorio es-ES…) et les
  déplacements personnalisés. Plus AUCUNE variable d'environnement.
- `nyx.ico` (lune + constellation, miroir de l'icône adaptative Android,
  6 tailles 16→256 px) livrée à côté du jar → `IconLocation` réelle.
- Vérification d'existence du .lnk après `Save()` + codes de sortie
  dédiés (2/3) + chemin résolu imprimé — un échec n'est plus jamais
  silencieux.
- Lanceur `nyx-messenger.bat` : sans argument → `javaw.exe` (plus de
  fenêtre console résiduelle derrière l'application) ; avec `--selftest` →
  `java.exe` console (diagnostics conservés).

### 2. Restauration complète des sauvegardes de compte (miroir Android)

- **Portage miroir** de `crypto/PasswordCrypto.kt` (enveloppe nyx-enc-v1,
  mêmes paramètres PBKDF2/AES-GCM que le téléphone) et de
  `crypto/IdentityBackup.kt` (JSON v1/v2 + clé nue) — desktop déjà doté
  d'`org.json`, zéro nouvelle dépendance.
- `desktop/BackupRestore.kt` (sans état, testable) : export v2 (clé +
  alias + profil + contacts + curseurs) et application de restauration à
  l'identique de l'Android — identité re-dérivée, alias normalisé, profil
  propre, contacts re-fusionnés **sans jamais régresser l'état local**
  (incoming local + accepted sauvegardé → mise à niveau ; archivé local →
  intact), curseurs inbox en insertion seule.
- Onboarding : bouton **« Importer un fichier de sauvegarde… »**
  (sélecteur natif), collage multi-format (enveloppe/JSON/clé), champ mot
  de passe qui apparaît automatiquement pour les fichiers chiffrés,
  messages d'erreur explicites (mot de passe incorrect, contenu
  méconnaissable, fichier tronqué).
- Réglages → **« Sauvegarde de compte »** : export d'une enveloppe
  chiffrée (mot de passe choisi) **importable par le téléphone** — la
  sauvegarde devient bidirectionnelle PC ↔ Android.

## Validation

- **142 tests JVM verts** (121 existants + 21 nouveaux : PasswordCryptoTest,
  IdentityBackupTest miroir Android, PasswordCryptoInteropTest,
  BackupRestoreTest).
- **Vecteur d'interopérabilité indépendant** : une enveloppe scellée par
  une implémentation tierce (Python cryptography, paramètres Android
  exacts) est déchiffrée intacte par le desktop — le trajet réel
  téléphone → PC est couvert par un test de régression permanent.
- Selftest headless `--selftest` : nouvelle étape « sauvegarde »
  (export → enveloppe → déchiffrement → import complet + mauvais mot de
  passe refusé).
- Installateur : `go vet` OK (cibles windows + linux), smoke Linux complet
  (SHA payload, essentiels, icône, selftest du jar installé).
- Audit `audit.py --strict` : PASSED (rapport joint à la release).

## Mise à jour

Relancer `nyx-messenger-windows-v0.3.2-installer.exe` **par-dessus** la
version installée : mise à jour en place (données
`%USERPROFILE%\.nyx-messenger` préservées), raccourcis recréés au bon
endroit avec l'icône. Pour restaurer le compte téléphone : premier écran →
« J'ai déjà une identité » → « Importer un fichier de sauvegarde… » →
choisir le fichier → saisir le mot de passe du compte téléphone.
