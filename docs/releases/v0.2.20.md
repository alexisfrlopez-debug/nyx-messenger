## 1. Correctifs APPELS (retour terrain : « l'appel vocal n'aboutit pas, le destinataire reçoit une notification mais ne sonne pas »)

Diagnostic sur les logs 08:08 (Xiaomi appelant) : « connexion directe impossible : Connect timed out » ×2 — un SEUL essai de 40 s partait immédiatement après l'offre, alors que le destinataire ne la connaît qu'après son poll (~15 s) et qu'un circuit onion entrant peut prendre 10-30 s. L'appel était mort avant même la sonnerie.

- **Fenêtre de connexion média** : essais de 12 s toutes les 3 s pendant 75 s (au lieu d'un seul essai 40 s) — le pair sonne et accepte pendant ce temps ; attente de réponse après connexion : 60 s ; watchdog « appel manqué » côté appelé : 120 s.
- **Garde « média avant offre »** (course journal/poll) : côté appelé, une connexion d'appel arrivant AVANT l'offre est GARDÉE 90 s (au lieu d'un refus net qui tuait l'appel) et adoptée dès que l'offre arrive.
- **Sonnerie audible** : canal de notification dédié « Appels entrants » (importance HAUTE + sonnerie par défaut + vibration — l'ancien canal contacts ne sonnait pas) ; la notification est retirée à l'acceptation/refus/raccroché.

## 2. VISIO (demande : « l'appel visio » — le bouton 🎥 de v0.2.18 annonçait un report)

- **Vraie visio** : Camera2 → encodeur MediaCodec **H.264** (~320×240 @ 15 fps, 150 kbps, taille choisie parmi celles supportées par la caméra) → trames `F_VIDEO` sur le MÊME canal direct onion-to-onion que l'audio (port 47471, chiffré Tor de bout en bout, zéro réplica, zéro stockage). Décodeur H.264 → surface distante.
- **Négociation** : le csd H.264 (SPS+PPS) voyage dans le HELLO (`vcsd`) et le F_CALL_ACCEPT (payload JSON `{csd,vcsd}` — format historique brut conservé pour un pair v0.2.19 sans vidéo). Caméra indisponible/refusée = **repli audio-only** (jamais d'appel raté pour ça).
- **UI** : rendu distant plein écran + aperçu local en picture-in-picture ; bouton caméra marche/arrêt pendant l'appel ; **aucune image ne part avant acceptation** (`transmit` verrouillé, comme l'audio).
- **Budget Tor** : ≈19 Ko/s par sens pour la vidéo + 3 Ko/s audio — le gel de l'image (et non la coupure) dégrade la visio si le circuit ralentit.

## 3. MISE À JOUR AUTOMATIQUE — version NORMALE uniquement (demande : « la version "normale" se met à jour toute seule, quand la dernière release est validée pour la production »)

- **Validation = publication** : chaque version part en PRÉ-RELEASE ; la passer non-pré-release (« latest » sur GitHub) EST l'acte de validation — aucune release non validée n'atteint les apps standard.
- **Flux** : vérification de `releases/latest` au démarrage puis toutes les 6 h, via l'API GitHub **à travers Tor** (aucune connexion hors Tor) ; si la version validée est plus récente → **téléchargement automatique** (~23 Mo via Tor, patient) dans le cache → notification « Mise à jour prête » + carte Paramètres (état temps réel) → appui = installateur système (la confirmation Android reste obligatoire — c'est une garantie, pas une limite).
- Les builds **test/test2** sont exclus (ils valident via le plan de tests ci-dessous).
