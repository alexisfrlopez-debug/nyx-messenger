# v0.2.42 (versionCode 46)

## Correctifs terrain (retour opérateur, session 63)

### Mise à jour invisible — protocole de secours réseau (BUG n° 1)

Retour : « logs envoyés, l'application ne voit pas la mise à jour ». CAUSE
RACINE : l'API REST `api.github.com` limite les requêtes non authentifiées à
60/h **par IP** ; via Tor les IPs de sortie sont PARTAGÉES par des milliers
d'utilisateurs → quota épuisé quasi en permanence → HTTP 403 → l'app ne voyait
JAMAIS les nouvelles releases.

Chaîne de résolution à TROIS maillons (tous via le SOCKS Tor), stratégie
ADAPTATIVE (le maillon qui a réussi devient la voie rapide du cycle suivant) :
1. API REST (officielle — quand le quota le permet) ;
2. flux Atom `releases.atom` (canal test, pré-releases incluses) /
   redirection `releases/latest` (canal standard) — servis par l'infrastructure
   WEB github.com, NON soumis au quota API ;
3. `releases/expanded_assets/<tag>` — fragment HTML donnant l'URL exacte de
   l'APK (le nom contient un horodatage, impossible à construire du seul tag).

Bonus fiabilité du téléchargement : REPRISE HTTP Range (le `.part` est conservé,
3 tentatives — les circuits Tor peuvent se rompre en cours de flux) et
VÉRIFICATION SHA-256 contre le `SHA256SUMS` de la même release (defense-in-depth
par-dessus TLS). Échec réseau → nouvelle tentative à 2 min au lieu d'attendre
un cycle complet.

### Bouton d'export de logs illisible (BUG n° 2)

Retour : « le bouton d'envoi de logs devient illisible une fois les logs
envoyés ». CAUSE RACINE : le `Text` de statut de la ligne compacte n'avait
AUCUNE contrainte de largeur — un statut long (nom de fichier de 60+
caractères) écrasait le titre (poids 1f → largeur 0) et débordait de la carte.
Correctif : statut COURT dans la ligne compacte (contraint : poids + ellipsis,
aligné à droite), flèche de dépliage en dernier ; nom de fichier complet
uniquement dans la vue dépliée.

### Cap d'appel à 4 minutes

Bug fonctionnel terrain : `GLOBAL_CALL_CAP_MS` (240 s) coupait TOUT appel,
y compris une conversation ACTIVE à 4 min. Désormais : cap DISTINCT par phase
— ACTIVE = 2 h (anti-collé), le filet global 4 min ne s'applique plus qu'aux
phases transitoires (sonnerie, WAIT) où il est légitime.

### Saut d'événements silencieux au failover réplica

Le curseur d'inbox était toujours lu/écrit sous `replicas.first()` alors que
le relais suit `replicaIndex` (failover v0.2.25) ; les `gid` n'étant pas
alignés entre réplicas, le failover pouvait SAUTER DÉFINITIVEMENT des
événements. Le curseur est désormais persisté SOUS LE RÉPLICA INTERROGÉ.

## Durcissement (audit complet session 63)

- **Serveur Go** : corps HTTP BORNÉS avant décodage (API 256 Ko, gossip 5 Mo,
  admin 1 Mo — DoS mémoire) ; TIMEOUTS sur les serveurs HTTP (une connexion
  lente n'occupe plus un goroutine pour toujours) ; `identity.json` n'est plus
  régénéré sur erreur de lecture (EIO/permissions/montage) — seule l'absence
  du fichier régénère, toute erreur est fatale (perte d'identité impossible).
- **Anonymat** : User-Agent neutre constant `Nyx/1` (OkHttp envoyait par défaut
  `okhttp/4.x` — version de bibliothèque = version de l'app, corrélable côté
  serveur).
- **Console admin** : `network_security_config.xml` — la console Android
  refusait toute connexion cleartext vers les `.onion` sur Android 9+
  (même bug que le messager v0.2.6, jamais miroité sur la console).

Le rapport d'audit complet (80+ constats, axes redondance/fiabilité/rapidité/
protocoles de secours) est livré dans `livrables/documents/audit-complet-v0.2.42.md`.
