# Nyx Desktop v0.3.0 — la messagerie Nyx sur Windows (ADR-019)

**Première version desktop du messager Nyx** — portage Windows (Compose
Desktop, JVM) du client Android v0.2.53, demandé par l'opérateur (session 70 :
« je veux une version windows de cette application de messagerie »).

## Ce que fait cette version

- **Identité onion v3** : création locale (ed25519 → adresse onion), alias
  optionnel, restauration par clé de récupération (nyx1.…), sceau local
  AES-256-GCM + PBKDF2 (mêmes primitives que PasswordVault Android).
- **Tor embarqué** : tor.exe de l'expert bundle officiel 15.0.26, torrc
  généré (ports sondés, cookie auth, ConfluxEnabled 0, SafeLogging 1),
  démon piloté par le control port (ADD_ONION Flags=Detach — miroir de
  l'Android v0.2.34+), onion d'identité publié sur le port 80.
- **Réplique embarquée in-process** : portage de l'EmbeddedReplica Android —
  les 5 routes API servies par le PC quand l'app tourne, mêmes quotas
  (60 dépôts/min/auteur, 3 000 événements/48 MiB/500 par boîte, TTL 48 h),
  même authentification d'inbox (signature ed25519 ts:sig).
- **Messagerie complète E2E** (interop avec Android ≥ v0.2.41) :
  - messages texte (sealed box libsodium) ;
  - **fichiers/images** fragmentés (ChunkCodec — 96 Ko/fragment, 64 Mo max,
    sha256 vérifié à l'assemblage) ;
  - accusés ✓ (délivré) / ✓✓ (lu) ;
  - contacts : ajout par onion OU par alias (résolution réseau), invitations
    entrantes à accepter/refuser, blocage, suppression mutuelle ;
  - profils publics à visibilité par champ ; alias claim.
- **Routage fidèle** : dépôt = boîte du pair sinon flotte (DepositRouting),
  lecture = réplica propre en procédé + flotte, seq persistée par auteur
  avec auto-réparation (SeqResync sur 400), rendezvous signé embarqué
  (rendezvous.json + signature ed25519 vérifiée).
- **UI Compose Desktop** thème « Nuit de Nyx » : onboarding, conversations,
  chat (bulles, ✓✓, pièces jointes ouvrables), contacts, connexions (sondes
  /health), mon adresse (copie), réglages (thème, réplique on/off, profil,
  réplica perso, export journal, wipe).

## Livrables

- `nyx-messenger-windows-v0.3.0.zip` — **zip portable 100 % autonome**
  (114 Mo) : runtime Java 21 Temurin + Tor 15.0.26 + fat jar (libsodium
  win/linux/mac embarquée) + lanceur .bat + LISEZMOI.
- `nyx-messenger-windows-v0.3.0-installer.exe` — **installateur 1-clic**
  (117 Mo) : payload zip embarqué (`go:embed`), SHA-256 compilé en dur et
  vérifié à l'extraction, anti Zip-Slip, contrôles des fichiers essentiels,
  raccourcis Bureau + Menu Démarrer (redirections OneDrive gérées),
  désinstalleur préservant `%USERPROFILE%\.nyx-messenger`, `-silent`/`-dir`.

## Qualité

- **119 tests JVM verts** : 13 fichiers de test portés tels quels d'Android
  (OnionCodec, BootstrapReplicas, RendezvousList, LoopbackBind, ChunkCodec,
  DeleteCodec, DepositRouting, LinkFallback, ReceiptCodec, ReplicaCodec,

  desktop dépôt→inbox→curseur/séquence/inconnu, torrc, DesktopStore).
- **Audit strict PASSED** (0 CRIT / 0 MAJOR / 1 MIN préexistant TODO

  `portage-miroir` (justification fichier-entier pour les copies 1:1
  Android↔desktop, allowlist documentée).
- **Smoke tests réels** : installateur Linux (même code, payload identique)
  → extraction 324 fichiers + essentiels vérifiés ; jar extrait exécuté →
  libsodium chargée, onion v3 généré, identité persistée/relue, codec valide.

## Limitations v1 (cadrage opérateur session 70)

- Appels audio/visio : **phase 2** (pile MediaCodec Android non portable —
  ADR-019 §6) ; les signalisations d'appel reçues sont ignorées proprement.
- P2P direct (ADR-017) et NYX-LINK (ADR-018) : phase 2 — le journal
  répliqué reste le chemin v1 (le pair Android retombe dessus, comportement
  spécifié).
- Auto-update GitHub : phase 2.
- Le keystore Android n'est pas concerné ; pas de recompilation APK dans
  cette session (`android/` INTACT).
