# Nyx v0.2.3 — publication réseau réelle du client + sauvegarde d'identité

**Code 7** · deux livrables conformes à la règle release v0.2.2 : un APK **standard**
(`nyx-v0.2.3-…-release.apk`) et un APK **test** (`nyx-v0.2.3-…-test.apk`, gros
bouton rouge d'export des logs vers le dossier de travail Drive).

## Correctifs serveur (intégration des blocs A/P/P2 de la VM)

- **n°1 — adresse onion fantôme (clamp RFC 8032)** : tor interprète les 32 premiers
  octets du blob `ED25519-V3` comme un scalaire brut (aucune expansion sha512).
  `AdminPrivKeyB64()` envoie désormais `SHA512(graine)[0..32]` clampé
  (`h[0]&=248 ; h[31]&=127 ; h[31]|=64`) → l'adresse publiée = l'adresse déclarée.
- **n°2 — service onion éphémère** : la connexion contrôle qui a créé un service
  `ADD_ONION` est désormais maintenue ouverte (`Control.Watch()`) et la publication
  est re-jouée automatiquement si la connexion casse (redémarrage tor…).
- **n°3 — onion client jamais publié** : `nyx-server` publie maintenant l'API
  `/client/*` sur l'onion du nœud (`Port=80 → httpPort`) via `OnionScalarB64()`.

## Correctifs client (diagnostiqués sur les logs device 24094RAD4G / XPLORE1)

1. **Clamp tor côté app** — même bug que le serveur : l'app envoyait le blob
   libsodium `seed||pk` tel quel à `ADD_ONION` → « publication onion différée :
   ServiceID tor ≠ adresse calculée » et `replicas: aucun`. Corrigé dans
   `TorControlClient.publishOnionEd25519V3` (miroir d'`OnionScalarB64`).
2. **Réplicas jamais câblés** — `setReplicas()` n'était appelé nulle part : liste
   d'amorçage embarquée (`android/replica-bootstrap.properties`, git-ignoré) lue
   au démarrage ; le relais est reconstruit quand le port SOCKS (dynamique)
   change ; sonde `replicaHealth()` (GET /health).
3. **Création d'identité gatée** — « Créer mon identité » n'est actif que lorsque
   le réplica d'amorçage est joignable via Tor (sonde répétée toutes les 8 s,
   Tor démarre dès l'entrée sur l'écran d'onboarding). Fini les comptes créés
   « à sec » sans réseau.
4. **Sauvegarde + récupération réelles** — clé de récupération
   `nyx1.<base64>.<checksum>` affichée après création et dans Paramètres
   (copie + export fichier SAF, `crypto/IdentityBackup`) ; le bouton
   « Restaurer une sauvegarde » (jusqu'ici un stub TODO) restaure réellement :
   collage de la clé ou import du fichier, re-dérivation de la paire
   (`cryptoSignSeedKeypair`) — même adresse garantie, checksum anti-faute de frappe.
5. **Verrou biométrique** — le prompt est déclenché sur `ON_RESUME` (le délai
   fixe de 300 ms restait muet sur certains OEM — MIUI/HyperOS) ; les erreurs
   biométriques sont désormais **affichées** et journalisées (`nyx-lock`),
   le prompt se relance à chaque retour au premier plan.

## Signature et autonomie

- APK signés avec le **keystore de release** restauré (fingerprint
  `FF:68:F6:AB:FA:19:9F:38:9F:65:87:67:62:E9:C1:EF:C9:6E:26:77:ED:7C:0A:78:95:56:B0:5F:30:2C:99:9A`).
- ⚠️ Les APK 0.2.2-test installés sur les devices étaient signés debug :
  **désinstaller avant d'installer v0.2.3** (signature différente).
- Autonomie vérifiée sur les 2 APK : Tor embarqué 4 ABI, natives
  sodium/sqlcipher/jna 4 ABI, universel (pas de splits), zéro GMS, permissions
  minimales. Marqueurs diag (OAuth/logcat) présents **uniquement** dans le build test.

## Vérifications post-installation recommandées

1. Onboarding : attendre « Réplica joignable » avant « Créer mon identité ».
2. Noter la **clé de récupération** (papier, hors de l'appareil).
3. Bouton rouge (build test) → le zip doit apparaître dans `logs-app/` du Drive
   avec `publication onion` réussie dans le logcat.
4. Ajout de contact par `@alias` sur le réplica, échange 2 devices.
