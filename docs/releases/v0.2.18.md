## 1. FIX — progression d'envoi qui ne se termine jamais (expéditeur)

Le dépôt marquait l'état du **message** (« envoyé ») mais jamais celui de la **pièce
jointe** : la bulle restait « Transfert x sur y… » pour toujours, même quand les
fragments étaient partis (les logs terrain 06:08 le confirment : « ✓ fichier déposé
(1 fragments) » côté Blackview, « ✓ fichier assemblé » côté Xiaomi). Désormais
l'expéditeur pose l'état **prêt** (chemin local inclus) dès le dépôt complet — la
bulle passe média jouable, comme chez le destinataire.

## 2. Fichiers : RIEN sur le serveur quand c'est possible — canal direct P2P

Nouveau **canal direct téléphone-à-téléphone** : les deux clients publient déjà leur
service onion (identité) — un **second port (47471)** y est ajouté, mappé sur un
écouteur local authentifié (signature ed25519 de la clé d'identité + contact accepté
obligatoire). L'envoi d'un fichier tente **d'abord le chemin direct** : les fragments
chiffrés E2E passent d'un téléphone à l'autre et **le réplica n'en voit RIEN**.

- Pair joignable (cas normal : les deux apps actives) → **zéro stockage serveur**.
- Pair hors ligne (joignable ni en direct, ni en poll) → repli **transparent** sur le
  chemin historique : fragments chiffrés E2E (opaques pour le serveur) dans la boîte
  du réplica jusqu'au prochain poll — c'est le store-and-forward qui garantit la
  réception en absence ; le serveur ne peut pas les lire, jamais.
- Progression, assemblage, sha256, accusés : identiques dans les deux chemins.

## 3. Médias chiffrés AU REPOS sur les téléphones

- Base Room : DÉJÀ chiffrée (SQLCipher, clé scellée Keystore) — contacts, messages,
  fragments.
- Fichiers médias sous `filesDir/media/` : **DÉSORMAIS chiffrés AES-256-GCM** (clé
  dédiée scellée par le Keystore matériel). Lecture : déchiffrement EN MÉMOIRE
  (aperçu image, visionneuse) ; le lecteur audio écrit une copie temporaire dans le
  cache, supprimée à la sortie. Aucune donnée lible hors de l'app.
- Exports volontaires vers Téléchargements : restent lisibles (c'est l'utilisateur
  qui exporte — hors périmètre de l'app, documenté).
- Serveur : rien de nouveau — le réplica ne stocke rien au-delà des fragments de
  transit chiffrés du cas hors-ligne ci-dessus.

## 4. Appels audio + boutons dans le chat (ADR-015 livré)

**Boutons dans la barre du chat** : 📞 (appel audio) et 🎥 (visio). Verrou contact
mutuel identique aux messages ; un seul appel à la fois ; l'audio ne part qu'après
acceptation explicite.

- **Signalisation** : type « msg » existant, corps chiffré `kind=call`
  (offer/reject/bye) — zéro changement serveur ; latence = poll (≤ 15 s).
- **Média** : connexion DIRECTE onion-to-onion (port 47471) — AudioRecord 16 kHz →
  AAC-LC 24 kbps → trames sur le socket → décode AAC → AudioTrack. Mute + haut-parleur.
- **Écran d'appel global** : sonnerie entrante (notification prioritaire + overlay
  avec Accepter/Refuser), durée, raccrocher — visible depuis n'importe quel écran.
- **Traces** : « Appel manqué » / appel sans réponse insérés dans la conversation.
- **Visio** : le bouton est là et explique honnêtement — l'audio stable prime (la
  vidéo sur circuit onion arrive en v0.2.19) ; la latence typique d'un appel reste
  0,5-3 s, le prix de l'anonymat onion (ADR-010/015).

## 5. Les trois mots de passe (Paramètres → Mots de passe d'accès)

Hachés PBKDF2-HMAC-SHA256 (150 000 itérations, sel aléatoire, comparaison à temps
constant) — jamais transmis, jamais en clair. Saisis sur l'écran de verrouillage, à
la place de la biométrie (le prompt biométrique ne s'ouvre que si l'opt-in est actif).

| Mot de passe | Effet |
|---|---|
| **normal** | Ouvre l'application normalement (comme la biométrie). |
| **panic** | Ouvre une session LEURRE : contacts et historique apparents vides, réception et canal P2P coupés (le vrai compte est intact — messages en attente conservés côté réplica). Retour au compte réel au prochain déverrouillage normal/biométrique. |
| **destruction** | RESET IMMÉDIAT, sans confirmation : Tor arrêté, base (contacts/messages/accusés/pièces jointes) effacée, fichiers médias supprimés, préférences et identité détruites → l'app repart sur l'onboarding. Les exports volontaires vers Téléchargements ne sont pas touchés (hors de l'app). |

Gardes : mots de passe distincts obligatoires (le conflit est refusé) ; le mot de
passe destruction se supprime avec double confirmation dans les Paramètres (la
SUPPRESSION du mot de passe est l'opération dangereuse à guider, pas son usage).
