# Nyx v0.2.6

## Fix « réplica injoignable » — policy réseau Android (CLEARTEXT)

Cause racine prouvée par les exports de logs v0.2.5 (bouton rouge, deux
téléphones de l'opérateur, 2026-10-15) : la sonde réplica échouait en 1 à 4 ms
sur chaque tentative, sans même toucher le réseau :

```
nyx-conn: GET /health ÉCHEC (2 ms) : UnknownServiceException:
CLEARTEXT communication to 5myvqk….onion not permitted by network security policy
```

Depuis Android 9 (targetSdk ≥ 28), le HTTP en clair est interdit par défaut et
le contrôle porte sur le nom d'hôte de l'URL AVANT toute connexion — y compris
quand un proxy SOCKS est configuré sur le client : la requête n'atteignait
jamais le Tor embarqué. Conséquences en chaîne : réplica jamais validé →
création d'identité bloquée → l'app restait sur l'écran Connexions.

## Correctif

- **`android:networkSecurityConfig`** : nouvelle ressource
  `res/xml/network_security_config.xml` autorisant le cleartext UNIQUEMENT pour
  `*.onion` (réplicas, via Tor embarqué uniquement) et `localhost`/`127.0.0.1`
  (contrôle/diagnostic local). Le chiffrement est de toute façon assuré de bout
  en bout par le circuit Tor lui-même (ADR-007/ADR-009) ; tout le reste du
  trafic reste soumis à l'interdiction par défaut.
- Aucun autre changement de code : le client SOCKS (`RelayClient`), l'écran
  Connexions (v0.2.5) et le bouton rouge restent inchangés.

## Vérifications livrées

- Policy `cleartextTrafficPermitted` présente dans les 2 APK (contrôle aapt2
  sur la ressource compilée 0x7f100000, manifest + domaine onion).
- Marqueurs dex : réplica d'amorçage 5myvqk….onion embarqué dans les 2 APK ;
  credentials Drive (folderId + refresh token) présents UNIQUEMENT dans le
  build test — le build standard n'embarque aucun secret.
- Audit pré-compilation strict : PASSED (0 critique, 0 majeur, 3 infos TODO).
- Autonomie 13+13 contrôles : signature 1 clic, Tor embarqué 4 ABI, APK
  universel unique, permissions minimales, zéro GMS.
