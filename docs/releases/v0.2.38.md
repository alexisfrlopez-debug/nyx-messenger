# v0.2.38 (versionCode 42) — PRÉ-RELEASE

## Correctif principal — « l'écran principal de la messagerie ne défile pas »

Retour opérateur 22/10 (v0.2.36-test sur Blackview XPLORE 1) : « l'écran
principal de la messagerie ne défile pas, il faudrait vérifier
systématiquement le défilement de toutes les fenêtres » — RÉCIDIVE
malgré le correctif v0.2.31 (onglets confinés à la hauteur restante).

### Cause racine (structurelle : la zone fixe n'avait AUCUN plafond)

L'écran principal empile, AU-DESSUS des onglets défilants, une zone FIXE :
bannière Tor + ligne d'état réplica (multi-lignes en cas d'erreur —
l'appareil était en « publication onion : erreur Tor 550 ») puis, sur le
build TEST, la carte d'export de logs (~170 dp dépliée : gros bouton
rouge 72 dp + partage) et la carte plan de tests (~116 dp repliée).
Le correctif v0.2.31 confinait la zone d'onglets à la **hauteur
restante** (`Box.weight(1f)`) — mais si la zone fixe occupait à elle
seule plus que l'écran (appareil compact, grande police
d'accessibilité, bannières d'erreur multi-lignes, cartes dépliées), le
« restant » tombait à **~0 px** : la liste mesurée sur un espace nul ne
pouvait plus défiler du tout, et l'essentiel de l'écran (les cartes
fixes) ne défilait pas non plus — plus rien ne bougeait.

Le poids des éléments par version rendait le bug insidieux :
v0.2.31 (2 cartes repliées pesaient moins) → écran correct sur l'appareil
de test ; v0.2.35 (bannières + erreur Tor longue) → la marge a fondu.

### Correctif — défilement garanti PAR CONSTRUCTION

1. **Zone fixe PLAFONNÉE** à 40 % de la hauteur du corps
   (`ScrollPolicy.HEADER_MAX_FRACTION`, `BoxWithConstraints` +
   `heightIn(max = …)`) : elle défile **EN INTERNE** si son contenu
   dépasse le plafond — les cartes de diagnostic restent intégralement
   atteignables en tout état de cause.
2. **Zone d'onglets garantie** : elle reçoit TOUT le restant
   (`weight(1f)`, unique enfant pondéré) — au moins 60 % de l'écran
   moins le chrome des onglets (`ScrollPolicy.listMinDp`). L'invariant
   (fixe + liste + chrome = corps, liste ≥ 50 % sur un téléphone) est
   **verrouillé par `ScrollPolicyTest`** (6 tests JVM, même motif que
   `NyxContrastTest` pour la palette v0.2.36) : aucune « simplification »
   du plafond ne repassera inaperçue.
3. **Cartes de diagnostic REPLIÉES par défaut** (build test) :
   - carte d'export de logs : une LIGNE compacte (titre + état + ▶) —
     l'état (collecte…/envoi…/déposé/erreur) reste visible DANS la ligne
     même repliée ; le gros bouton rouge + partage s'ouvrent au clic ;
   - carte plan de tests : consigne masquée repliée (titre + progression
     restent), contenu défilant déjà confiné à 260 dp (v0.2.32).
   Zone fixe en pratique : ~150 dp repliée (contre ~570 dp avant) — la
   liste occupe l'essentiel de l'écran, comme sur le build NORMAL.

### Audit systématique du défilement — toutes les fenêtres

| Fenêtre | Structure | Verdict |
|---|---|---|
| Écran principal (conversations/contacts/blocages) | zone fixe plafonnée + onglets défilants | **CORRIGÉ v0.2.38** |
| Chat — messages | `LazyColumn(weight 1f)` + barre de saisie | OK (zone fixe bornée ~250 dp) |
| Chat — fichiers & médias | `LazyColumn(weight 1f)` | OK |
| Réglages | `Column(verticalScroll)` plein écran | OK |
| Mon profil (édition) | `Column(verticalScroll)` | OK |
| Fiche contact | `CenteredScrollColumn` | OK |
| Mon adresse | `CenteredScrollColumn` | OK |
| Verrou | `Column(verticalScroll)` (v0.2.31) | OK |
| Connexions / Onboarding | `ScreenColumn` (`verticalScroll`) | OK* |
| Sélecteur « nouvelle conversation » | `Column(verticalScroll)` interne | OK |
| Appel (overlay) | écran fixe dédié | OK par conception |

\* `ScreenColumn`/`LockScreen` centrent leur contenu (`Arrangement.Center`)
  dans une colonne défilante : depuis Compose Foundation 1.4 (projet en
  BOM 2024.09 → Foundation 1.7), un contenu centré plus haut que le
  viewport est replacé en haut — le haut reste atteignable. Aucun
  correctif nécessaire.

Console admin : les panneaux (flotte, réplicas, journal) sont des
`LazyColumn`/zones défilantes existants — audit passé en revue, aucun
changement requis côté v0.8.6.
